# reservation-sim 백로그

> 기준 문서는 `SPEC.md`(1.4.1). 단계(M0~M9)와 완료 기준은 SPEC 18장, API·DB 세부는 `API_SPEC.md`·`DB_SPEC.md`.
> 이 파일은 작업 단위, 선행 관계, 진행 상태를 관리한다. 항목을 끝내면 상태와 근거(커밋, 테스트, 실행 ID)를 함께 적는다.

**상태**: `할 일` → `진행` → `검토` → `완료` (막히면 `보류` + 사유)
**우선순위**: P0 = 없으면 실험 자체가 성립하지 않음 / P1 = 비교 실험에 필요 / P2 = 관찰·편의

---

## 완료 정의 (모든 항목 공통)

- [ ] SPEC의 해당 절과 16장 테스트를 만족한다. 테스트와 구현이 다르면 SPEC 기준으로 다른 쪽을 고친다 (테스트 기대값을 구현에 맞추지 않는다).
- [ ] 버그 수정은 **고치기 전 코드에서 테스트가 먼저 실패**하는 것을 확인한 뒤 고친다.
- [ ] 고친 코드를 빼면 테스트가 실패하는지 확인한다 (테스트가 실제로 검증하는지).
- [ ] API 응답은 실제 서버 테스트로 검증하고, 가짜 응답은 `contracts/*.json`에서 만든다.
- [ ] 명세에 없는 결정은 에이전트별 결정 기록(`decision.md` / `DECISION_CLAUDE.md`)에 남긴다.
- [ ] 측정값을 남기는 실행은 bench(SPEC 10.4)에서만 한다.
- [ ] 로컬 커밋 (push 하지 않음).
